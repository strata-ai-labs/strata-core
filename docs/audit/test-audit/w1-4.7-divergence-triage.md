## Open product calls (needed before executing the ACCEPTs / the #2700 fix)

1. **#2700 lifecycle unification direction.** The issue wants branch/space consistency; the
   recommended direction is **tighten spaces toward branch semantics** (dup-create errors,
   auto-create off, missing-delete errors) — it kills the invisible-tenant hazard and treats
   both scoping axes as explicit. The alternative (make branches lazy like spaces) is *not*
   recommended: branches are versioned lineage and an explicit lifecycle is correct. This is a
   breaking change to the current lazy-space convenience, so it needs a deliberate call.
2. **Confirm the three ACCEPTs.** Accepting locks V1 contract: batch has no engine-side cap;
   `json_scan` is a seek, not a prefix filter; `as_of` coverage stays patchy for V1. Each is
   defensible, but it is a product-contract decision, not a test decision.

## Recommended W1 execution order

1. **#2694** — `event_range` reverse (high-severity, self-contained). *(this slice)*
2. **#2695** — range endpoint inclusivity (small, adjacent to #2694).
3. **#2704 catalog wire name** — api-contract, small, high DX value.
4. **#2701 failure channel** — unify itemwise across kv/json/event.
5. **#2700** — the branch/space cluster (resolution + naming + lifecycle), gated on decision (1); the largest and most semantic.

The three ACCEPT entries become ledger annotations (bug-pin → accepted-contract) once decision
(2) lands — the ledger header already admits "an explicitly-deferred contract decision" as a
valid entry class, so no schema change is needed, only a per-entry reclassification note and
closing the corresponding issues as accepted V1 contract.
